# Pre-release regression review

The last published release is **v0.30.0**, commit
`ab8e713d0597843bf2fbc3151701a38e4aba9989`. Tags v0.31.0 and v0.31.1
exist, but their release workflows failed before publication. The v0.31.1
failure was the dependency audit's glob/minimatch advisories; the package
upgrades in #539 and the successful audit on #545 address that blocker.

## Scope and prior findings

This review follows [the static review of the v0.30.0 diff through
e4e79633](REGRESSION-REVIEW-ab8e713d.md), rechecks its three findings, and
reviews the subsequent production changes: cross-language navigation and live
buffers, diagnostic load/refusal lifetimes, sidecar request disposal, test
discovery targets and file watching, NuGet updates, and test-host caching.
This is a review of changed behavior, not a claim that static inspection proves
every possible runtime input correct.

The contributor-film submodule archive was removed; the Shop set excludes the
MoveType demo; and lspkit is hash-verified and extracted outside the final
directory before a successful rename. The earlier three findings are addressed.

## Confirmed regressions and fixes

All four update findings implement [NUGET-REQUESTS-UPDATE-CONFIRM] and
[NUGET-XML-DOM].

| Finding | Before | Result and evidence |
| --- | --- | --- |
| Shared consumers change during confirmation | `sameProposal` ignored `affectedProjects`, so an update could affect projects the confirmation never named. | The complete ordered consumer list must match. The existing panel interaction test now runs declaration-change, consumer-added and consumer-removed permutations; the two new permutations failed before the fix and pass afterward. |
| Compact project XML omitted from CPM previews | A reference was recognized only when its XML tag began a physical line. | `quick-xml` reads the canonical package inventory; the real CPM integration test now keeps the sibling project's reference on the same line as the rest of its XML. It failed with the sibling absent and now passes with both consumers present. Inherited conditions and item metadata remain ineligible for consolidation. |
| Explicit version changes on shared props fail | The version picker was routed through a project-only guard and attempted `dotnet list` on props. | Exact picker selections reuse the host's props inventory, identify the selected props as the owner, and list only its actual consumers. `explicit_props_version_selection_preserves_shared_target_and_rejects_stale_edits` exercises both props-file kinds, F# and C# consumers, a nested overriding props file, mutation and stale rejection. The original guard failure was reproduced first. |
| Explicit version changes cannot replace a range | The picker was told to use explicit selection, but rejected the range even after an exact version was selected. | Default proposals still reject ranges; explicit proposals retain the original requested declaration for stale validation and classify the exact selected version. `explicit_version_picker_can_replace_a_range_only_after_preview` reproduces the rejection and verifies preview, exact mutation and stale rejection for real F# and C# projects. |

## Verification

- All **40 NuGet integration tests** pass: 34 existing request/edit/consolidation
  cases and six bounded/explicit update cases, using the real host, sidecars,
  SDK and a controlled local package feed.
- All seven existing XML inventory tests pass, including the added inherited
  condition assertion. The condition assertion failed before its guard was added.
- The **26 NuGet panel interaction tests** pass in VS Code, including the three
  stale-preview permutations. The initial full browser run also identified that
  the manually launched host had no staged binary; the panel-only run isolates
  the intended interaction checks, and the full pipeline stages its own payload.
- Rust formatting and strict all-target clippy pass; VS Code formatting,
  ESLint and TypeScript checks pass. Deslop scans before and after the changes
  retain 6.5% duplication for the extension and report 1.9% in the NuGet host
  module; the new ownership module introduces no reported cluster.
- #545 merged after 61 successful checks and two intentional skips. The new
  test-host cache workflow passed on both Linux and Windows on that merged
  commit ([run 41589382215](https://github.com/Nimblesite/SharpLsp/actions/runs/41589382215)),
  exercising the previously unverified workflow before the follow-up PR uses it.

The follow-up PR's complete CI and release publication remain separate gates;
focused test results alone do not authorize declaring either gate successful.

## Historical scratch reconciliation

The seven older stashes were inspected against their own original bases rather
than merged as old branch snapshots. The ignore rules, workspace file and Razor
work already exist in the reviewed tree. The old CI stash is superseded by the
current build/test boundary: its remaining consumer staging helper has no caller,
its proposed test expectation contradicts the current npm script, and its review
predates the implemented NuGet update fixes. Those obsolete variants are not
restored. The remaining stash contains only ignored Deslop cache artifacts.

The complete repository Deslop scan passes the unchanged **5.85%** gate at
**5.3%**, over 939 source files.
